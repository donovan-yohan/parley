# Parley

Parley is a multi-agent storytelling and roleplaying layer built on top of
Belayer and Hermes. The repo contains a local, file-backed vertical slice:
a small Twine-style web app with three playable scenario packs, reusable NPC
records, truth/memory artifacts, visual prompt metadata, deterministic DM
handling for off-path player actions, SSE-driven live UI, and real portrait and
background generation via Belayer talent profiles.

If you materialize a world instance and connect Belayer, you can now see real
portraits and backgrounds appear live as the story plays out.

## Architecture Overview

Parley is layered. Each layer has one job:

- **World templates** (`worlds/<world-id>/`) — slow-changing authored canon. Seed
  material for new instances. Gameplay agents do not read template roots.
- **World instances** (`instances/<world-id>/<instance-id>/`) — materialized at
  runtime from a template. Each instance owns a Belayer crag. NPC state and
  memory accumulate here across stories.
- **Story instances** (per playthrough under each world instance) — own
  per-story `events.jsonl` and `scene-pulse.json`. Many stories can run inside
  one world instance.
- **NPC talent profiles** (`~/.hermes/profiles/blyr-<crag>-<character>/`) —
  Belayer-managed, per-crag persistent memory. Private NPC memory accumulates
  in each profile's `MEMORY.md` across stories.
- **Art talents** (`background-artist`, `portrait-artist`) — also materialized
  per crag. They generate world visuals via the Hermes `image_generate` tool.
  Parley does not call image APIs directly.

Zod contract schemas live under `src/contracts/`. The JS runtime imports
validators by injection — no `.ts` imports from `.js` runtime files.

## What You Can Run

The app currently ships three example scenarios:

| Scenario | ID | Default player action | Primary NPCs |
| --- | --- | --- | --- |
| Last Lantern Tavern | `last-lantern` | `I ask who remembers the old north road.` | Mara Underbough |
| Neon Afterhours | `neon-afterhours` | `I ask who signed the audit lockout.` | Veyra Sol, Kestrel-9 |
| Mossgrove Orchard Row | `orchard-welcome` | `I ask who keeps leaving lantern pears at my gate.` | June Bellweather |

Each scenario writes runtime artifacts under `instances/<world-id>/<instance-id>/<story-id>/state/`
after materialization. If you haven't materialized yet, the runtime falls back
to `worlds/<world-id>/state/` via a backward-compat path in `parleyRuntime` so
legacy unmaterialized scenarios still work out of the box.

## Prerequisites

### Required for the local Parley app

- Node.js 20 or newer.
- A POSIX-ish shell for the smoke scripts.

There are currently no npm dependencies, but running `npm install` is harmless if
you want a lockfile-aware workflow later.

### Required for materialized instances and NPC memory

Belayer is the runtime substrate for NPCs in materialized world instances. Every
named NPC corresponds to a per-talent Hermes profile fork. You need a recent
Belayer build that supports:

```bash
belayer crag --help
belayer team generated --help
```

Before running a materialized instance, ensure Belayer is authenticated and the
daemon is running:

```bash
belayer auth ensure
belayer daemon &
```

Older builds may expose generated talents under `belayer talent generated`; the
smoke script accepts either form. If your installed `belayer` is stale, point the
smoke at a source-built binary instead:

```bash
BELAYER_BIN=/path/to/belayer ./scripts/smoke-last-lantern.sh
```

### Required for image generation

Portraits and backgrounds are generated by the `portrait-artist` and
`background-artist` Belayer talents using the Hermes `image_generate` tool.
To enable image generation, configure a Hermes provider that exposes
`image_generate` (e.g. the Hermes OpenAI or Replicate provider config).

Without a Hermes image provider, the app still runs — portrait/background
fields stay in `prompt_ready` state and no images are written.

### Required for Hermes / agent workflows

Hermes Agent installed and authenticated for your provider(s). GitHub auth
available to `gh` if agents will open issues or PRs.

Parley's product boundary:

- Belayer owns generic runtime/control-plane mechanics: crags, climbs, generated
  talent records, agent spawn/roster/mail/events/artifacts, and generic gates.
- Parley owns story concepts: worlds, scenes, turns, characters, lore, rumors,
  truth verdicts, UI, and world/art metadata.

Do not make Belayer story-aware.

## Start the Local App

### First-time: materialize a world instance

Before running a materialized scenario for the first time, create a world
instance and bring up the Belayer daemon:

```bash
npm run instance:materialize -- --world last-lantern --as last-lantern-default
belayer daemon &
npm start
```

Materialization writes the instance layout under
`instances/last-lantern/last-lantern-default/`, creates the Belayer crag, and
scaffolds per-talent Hermes profiles for each named NPC. You only do this once
per instance.

### Already materialized

From the repo root:

```bash
npm start
```

By default the server listens on `127.0.0.1:4173`:

```text
http://127.0.0.1:4173
```

You can override the host or port when needed:

```bash
HOST=127.0.0.1 PORT=4289 npm start
```

Open the URL in a browser. Use the scenario selector in the right-hand panel to
switch between Last Lantern, Neon Afterhours, and Mossgrove Orchard Row.

## Play the Three Scenarios Manually

### Last Lantern Tavern

Select **Last Lantern Tavern** and submit:

```text
I ask who remembers the old north road.
```

Expected high-level result:

- Mara Underbough responds.
- The old north road / Ashford thread is recorded as rumor, lead, and unresolved
story memory.
- Mara appears as a reusable, resumable NPC.

To exercise the DM detour handling, try:

```text
I leap onto a table, claim I own the Last Lantern now, and demand everyone hand over their secrets.
```

Expected high-level result:

- The attempt is allowed as a disruptive action.
- The tavern ownership claim is rejected as unsupported canon.
- A social consequence is recorded.
- The red-scarfed drover route is surfaced as a story attractor.

### Neon Afterhours

Select **Neon Afterhours** and submit:

```text
I ask who signed the audit lockout.
```

Expected high-level result:

- Veyra Sol and Kestrel-9 are introduced.
- The Meridian faction / maintenance-order thread is tracked.
- The cyberpunk theme and visual prompt metadata are visible.

To exercise detour handling, try:

```text
I smash the badge reader, declare I am the compliance director, and order Kestrel-9 to delete every audit log.
```

Expected high-level result:

- Equipment damage triggers a soft-lockdown consequence.
- The false compliance authority / erase-logs claim is rejected.
- The checksum and blank-node route is surfaced as the next path.

### Mossgrove Orchard Row

Select **Mossgrove Orchard Row** and submit:

```text
I ask who keeps leaving lantern pears at my gate.
```

Expected high-level result:

- June Bellweather responds.
- Lantern pears, blue cloth, and the old press shed become the active cozy-story
threads.
- June appears as a reusable, resumable NPC.

To exercise detour handling, try:

```text
I demand the mayor arrest every neighbor and threaten to salt the fields unless someone confesses.
```

Expected high-level result:

- The threat is allowed as something the player says/does.
- The coercive claim is rejected as unsupported truth.
- June and the neighbors become guarded.
- The route back is repair through apology/help rather than hard railroading.

## Live Reactions and Generated Visuals

Once you have a materialized instance running with Belayer and a Hermes image
provider configured, the UI upgrades from static fixture responses to a live
event stream:

- The server emits **SSE events** on the `/api/events` stream as the story
  progresses. The client listens and patches the UI in real time — no page
  reload required.
- The `portrait-artist` talent wakes inside the world crag and calls Hermes
  `image_generate` using the character's composed portrait prompt. The resulting
  image lands in `instances/<world>/<instance>/world/assets/portraits/` and the
  UI swaps in the real portrait as soon as the SSE `portrait.generated` event
  arrives.
- The `background-artist` talent does the same for scene backgrounds, writing to
  `instances/<world>/<instance>/world/assets/backgrounds/`. A `background.generated`
  SSE event triggers the scene art swap.
- NPC private memory accumulates in each talent's Hermes profile
  (`~/.hermes/profiles/blyr-<crag>-<character>/MEMORY.md`) and persists across
  stories within the same world instance. Characters remember you.

For a full end-to-end walkthrough — including example SSE output, asset manifest
inspection, and crag diagnostics — see
`docs/devlogs/2026-05-04-belayer-profile-coupling-demo.md`.

## Test and Smoke Commands

Run the full Node test suite:

```bash
npm test
```

Run the Zod contract type-check:

```bash
npm run typecheck
```

Run Zod schema contract tests:

```bash
npm run test:contracts
```

Run the runtime smoke for the default Last Lantern turn:

```bash
npm run smoke:runtime
```

Run all scenario-pack smokes:

```bash
npm run smoke:scenarios
```

This verifies all three scenario packs, their default turns, durable state writes,
truth/memory artifacts, and scenario-specific NPCs.

Run the browser/client smoke:

```bash
npm run smoke:e2e
```

This starts an in-process server harness and verifies that the client loads,
scenario selection works, the turn form calls `/api/turn`, visual prompt metadata
is displayed, and state artifacts are persisted.

Validate artifact roundtrip (Zod contract layer + optional smoke):

```bash
npm run validate:pr10 -- --with-smoke
```

Materialize a world instance:

```bash
npm run instance:materialize -- --world <world-id> --as <instance-id>
```

Migrate a scenario seed from the old `crag` field to the `instance` field:

```bash
npm run migrate:scenario -- --scenario <scenario-id>
```

Run a Belayer doctor check (verifies crag/talent health without a full wakeup):

```bash
npm run smoke:belayer-doctor
```

Run the full Belayer wake transport roundtrip (requires `BELAYER_E2E=1`):

```bash
BELAYER_E2E=1 npm run smoke:belayer-roundtrip
```

Accept a world canon promotion from a talent evaluation:

```bash
npm run promote -- --eval <path-to-eval> --world <world-id>
```

Run everything commonly used for PR verification:

```bash
npm test
npm run typecheck
npm run test:contracts
npm run smoke:runtime
npm run smoke:scenarios
npm run smoke:e2e
git diff --check
```

Run the optional Belayer compatibility smoke:

```bash
BELAYER_BIN=/path/to/belayer ./scripts/smoke-last-lantern.sh
```

The Belayer smoke uses a temporary `BELAYER_HOME` by default. To inspect or reuse
that state yourself, provide one explicitly:

```bash
SMOKE_BELAYER_HOME=/tmp/parley-belayer-smoke BELAYER_BIN=/path/to/belayer ./scripts/smoke-last-lantern.sh
```

## Runtime Artifacts

For materialized instances, browser play writes artifacts under the
instance-scoped layout:

```text
instances/<world-id>/<instance-id>/
  world/
    canon/facts.jsonl
    state/world-state.json
    assets/
      manifest.json              # parley-asset-manifest/v1
      portraits/<id>.png
      backgrounds/<scene-id>.png
  stories/<story-id>/
    state/
      events.jsonl               # per-story append-only event log
      turns.jsonl
      truth-verdicts.jsonl
      promotion-candidates.jsonl
      promotions.jsonl
    scene-pulse.json             # read model for SSE-driven UI updates
  world-instance-evaluation.json # GM cross-story signal
```

For legacy unmaterialized scenarios, the runtime falls back to:

```text
worlds/<world-id>/state/
```

All files are created lazily as turns are submitted:

- `truth-verdicts.jsonl` is appended for every evaluated turn, including turns
  that fail truth validation.
- `turns.jsonl` is appended only for committed turns where the truth verdict is
  `pass`.
- `events.jsonl` is the per-story append-only event stream consumed by SSE.
- `scene-pulse.json` is the current read model that drives UI re-renders without
  polling.
- `world-instance-evaluation.json` carries GM cross-story signal and promotion
  recommendations.
- `assets/manifest.json` lists all generated art assets in
  `parley-asset-manifest/v1` format.
- `action-interpretations.jsonl`, `detour-scenes.jsonl`,
  `story-consequences.jsonl`, and `beat-redirects.jsonl` are appended only when a
  committed turn produces DM detour artifacts. Normal on-path turns may not create
  these files.

These are intentionally inspectable JSON/JSONL files. If local state gets noisy,
remove the relevant instance story state directory and restart the app.

## Development Notes

- Keep Parley story-aware and Belayer story-agnostic.
- Prefer local, file-backed, inspectable workflows until the runtime contracts are
  boring.
- TypeScript + Zod contracts ship under `src/contracts/` (PR #11). JS runtime
  imports validators by injection — no `.ts` imports from `.js` runtime files.
